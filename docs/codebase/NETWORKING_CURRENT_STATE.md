# NETWORKING_CURRENT_STATE.md

Covers `src/engine/layout/containment.ts`, `src/engine/layout/cidrAllocator.ts`, and `src/engine/simulation/networkFirewalls.ts` — the three files that together implement VPC/subnet/CIDR/NACL/Security Group behavior. Content below reflects a direct re-read of all three files during this pass (not carried over from prior summarization).

## 1. The core design principle: geometry is the source of truth

A service node's subnet membership, and a VPC's subnet CIDR allocation, are **never** trusted as data the user or a template set directly — they are recomputed from canvas positions on every render. `deriveSubnetForNode()` (containment.ts:124) is explicitly documented in its own comment as deriving subnet placement "using only the geometry of the boundary containers currently on the canvas — never the node's own previously-recorded `subnet` field, which is exactly the value being validated here." This is the single most load-bearing architectural decision in the networking layer: it means a node's declared `subnet` can never silently drift from where it visually sits.

## 2. VPC / Subnet / AZ containment (`containment.ts`)

- **Rect model**: every node (service or boundary) is reduced to `{x, y, width, height}`. Service nodes fall back to a fixed `120×80` estimate when unmeasured; boundary nodes fall back to `400×300`, deliberately chosen to mirror `BoundaryNode.tsx`'s own rendering fallback so containment math never disagrees with what's on screen.
- **Containment test**: `rectContainsPoint` is a simple axis-aligned bounding-box point test (inclusive on all edges). A node's rect is reduced to its **center point** before testing containment against subnet/VPC boundaries (`rectCenter`), i.e. containment is a center-in-rect test, not full-rect-inside-rect.
- **Ambiguity resolution**: when a node's center point falls inside more than one candidate boundary (nested boxes), `findSmallestContainingBoundary` sorts matches by `rectArea` ascending and picks the smallest — the innermost/most-specific container always wins. This single helper is shared by subnet lookup, VPC lookup, and (indirectly) security-group geometric legacy behavior, so all three containment questions in the app answer "what contains this" the same way.
- **`SUBNET_REQUIRED_SERVICE_IDS`** = `['alb', 'nlb', 'elb', 'app_runner', 'ec2', 'ecs', 'fargate', 'rds', 'aurora', 'elasticache']`. Any node with one of these ids that is **not** geometrically inside a `public_subnet`/`private_subnet` boundary is assigned `subnet: 'unassigned'` — a hard-fail state (see `REQUEST_SIMULATOR.md` §2). `api_gateway` is deliberately excluded (comment: it's a fully-managed regional/edge endpoint with no VPC placement, unlike an ALB/NLB). `nat_gateway` is also excluded from this list and instead gets its own fallback (`'private'` when unplaced) so the simulator's dedicated "NAT Gateway must be in a public subnet" message fires instead of a generic placement failure.
- **`DerivedSubnet`** = `'public' | 'private' | 'unassigned' | 'global'`. Anything not in `SUBNET_REQUIRED_SERVICE_IDS` and not `nat_gateway` defaults to `'global'` when unplaced (i.e. most services — Lambda, S3, DynamoDB, CloudFront, managed/serverless things — are modeled as not requiring subnet placement at all, consistent with real AWS).
- **VPC discovery**: `findContainingVpc` finds which `boundaryType === 'vpc'` node a subnet boundary's **own center point** sits inside, same smallest-area-wins rule. A subnet not inside any VPC boundary returns `null` (no address space to carve from).
- **Nested-boundary z-index**: `calculateBoundaryZIndex` computes containment depth (`getBoundaryContainmentDepth`, counting how many other boundaries geometrically contain this one via `isBoundaryContained`) and maps depth → z-index as `-4 + depth` (depth 0/outermost = -4, depth 4/innermost e.g. security group inside subnet = 0, deeper still climbs positive). `isBoundaryContained(child, parent)` requires the parent to have **strictly larger area** than the child, and either the child's center falls inside the parent, or there is ≥40% area overlap — this second clause exists to tolerate boundaries that are dragged so their center technically pokes outside the parent by a small amount while still being visually "inside" for most of their extent.
- **Security Group attachment is explicitly NOT geometric.** `getAttachedSecurityGroups(node, allNodes)` resolves purely by `node.data.securityGroupIds` (an explicit id-reference array the node carries), filtered to boundary nodes with `boundaryType === 'security_group'`. The code comment states this is a deliberate divergence from subnet/VPC placement: "this deliberately differs from subnet/VPC placement, which genuinely is geometric in real AWS — a Security Group is not." (This matches real AWS: an ENI can be geometrically anywhere in a subnet but is only protected by whichever SGs are explicitly attached to it.)

## 3. CIDR allocation (`cidrAllocator.ts`)

- **CIDR parsing/formatting** operates on IPv4 addresses reduced to a 32-bit unsigned integer (`base`) plus a `prefix` (0–32); `parseCidr` validates octet ranges (0–255) and prefix range (0–32) via regex + bounds checks, returning `null` on anything malformed rather than throwing.
- **`MIN_AWS_SUBNET_PREFIX = 28`** — hardcoded to match real AWS's actual minimum subnet size (a `/28` = 16 addresses). Enforced in two places: if the VPC's own CIDR is already smaller than `/28`, or if splitting the VPC evenly across the current subnet count would require a prefix larger than `/28`, `allocateSubnetCidrs` returns an explicit `error` string per subnet instead of a silently-wrong CIDR. The error message even tells the user the maximum subnet count their VPC size actually supports (`maxSubnets = 2 ** (28 - vpcPrefix)`).
- **Split algorithm**: given `n` subnets, `splitBits` is the smallest power-of-two exponent such that `2^splitBits >= n` (so 3 subnets → 4 equal blocks, with 1 spare — matches AWS's own VPC wizard convention and most real-world reference architectures, which favor round power-of-two subnet counts over exactly-sized allocations). Subnets are assigned blocks in **input order** (`index * blockSize` offset from the VPC base) — callers (`ArchitectureContext`) are responsible for sorting public-before-private, then top-left-to-bottom-right, before calling this function; the allocator itself has no positional awareness beyond array order.
- **Reserved addresses**: `getReservedAddresses` returns exactly the 5 addresses AWS reserves in every subnet, in the canonical AWS order/roles — Network Address (offset 0), VPC Router (offset 1), Amazon-Provided DNS (offset 2), AWS Future Use (offset 3), Network Broadcast Address (last offset, `blockSize - 1`). Returns `[]` for a `/31` or `/32` (correctly — there's no room to reserve 5 addresses in a 2-or-1-address block; AWS itself doesn't apply the standard 5-reservation model to `/31`s, which are point-to-point).
- **Usable host math**: `usableHosts = blockSize - 5` (clamped to 0), and `getUsableIpRange` returns `base+4` through `base + blockSize - 2` (i.e. immediately after the 4 low reserved addresses, up to immediately before the broadcast address) — this is arithmetically consistent with the reserved-address list above, and returns `null` for prefixes above `/30` where there's no usable range at all.

## 4. Firewall evaluation (`networkFirewalls.ts`)

Two independent layers, evaluated **in the real packet-flow order**: NACL first (stateless, subnet-wide), then Security Group second (stateful, instance-level) — and only if the NACL didn't already block.

### 4.1 `checkNetworkFirewalls(protocol, targetNode, boundaryNodes)`

- Finds the target's containing subnet via `findContainingSubnetBoundary`.
- **Custom NACL path** (`subnet.data.customNacl.inboundRules` present, rule-numbered): sorts rules by `ruleNumber` ascending (matching real AWS evaluation order — lowest rule number wins), and finds the **first** rule matching the protocol via a mixed strategy: matches the rule's `type` string against the protocol name case-insensitively, OR matches known port/type combinations for SQL (port 3306 / type "MySQL"), HTTP (port 80 / type "HTTP"), HTTPS (port 443 / type "HTTPS"), OR a catch-all `portRange === 'All'` rule. If no rule matches at all, the packet is **implicitly permitted** ("evaluated ... permitted: no matching rule") — this mirrors real AWS NACLs having an explicit final "* DENY" rule, but this codebase's custom-NACL matcher does not itself encode a real final-DENY-all fallback; it only blocks on an actual rule match with `action === 'DENY'`. This means a custom NACL in this app behaves as an **allow-by-default matcher over an explicit rule list**, not a true deny-by-default NACL, unless the template author has explicitly added a catch-all DENY rule with a high rule number. This is a genuine simplification relative to real AWS's implicit-deny-all-at-rule-32767 behavior, confirmed by reading the matcher logic (there is no synthesized final-deny check anywhere in this function).
- **Legacy/simple path** (`subnet.data.naclDenyInbound: string[]` present, no `customNacl`): a flat deny-list of protocol name strings; if the protocol is in the list, block; otherwise allow. No rule numbers, no CIDR matching, no port matching — this is the original, simpler NACL model this app started with, still used by any boundary node that hasn't been upgraded to the newer `customNacl` shape.
- If NACL blocked, the function returns immediately with `securityGroup: NOT_EVALUATED` — correctly modeling that a NACL-dropped packet never reaches the instance's Security Group.
- **Security Group path**: resolves attachment via `getAttachedSecurityGroups` (explicit `securityGroupIds`, not geometry — see §2), then filters to only groups that have been **explicitly configured** (`allowedProtocols !== undefined`, even if configured to an empty array). An attached-but-never-configured SG is treated as `NOT_EVALUATED`, not blocking — matching real AWS's default SG (which is created wide-open). Multiple configured groups are **unioned**: allowed if **any** attached group's `allowedProtocols` includes the protocol (correct real-AWS semantics — SG rules are additive/permissive across multiple attached groups, there is no cross-group AND).

### 4.2 `checkCustomNaclReturn(sourceNode, targetNode, boundaryNodes)`

A second, narrower function modeling **stateless NACL return-traffic** specifically: because NACLs (unlike Security Groups) don't track connection state, a response packet flowing back to the original client's ephemeral port range (1024–65535) must be explicitly permitted by an inbound rule in the **client's own subnet** NACL, not the server's. This function:
- Finds the source (client) node's containing subnet and its `customNacl`.
- Searches inbound rules for one matching an "ephemeral" port range (`portRange` containing `'1024-65535'` or the word "ephemeral" in either `portRange` or `type`).
- If no such rule exists, or the found rule is explicitly flagged `isMissingReturn`, the check **blocks** and returns a canned explanatory note describing the classic "stateless timeout" scenario (this is the mechanism behind the `nacl-custom-stateless-timeout` reference template/teaching scenario — see `TEST_SYSTEM.md` test 40 and `SERVICE_SYSTEM.md`/`COMPONENT_INVENTORY.md` notes on `NaclSideColumn.tsx`).
- This function is only invoked from `requestSimulator.ts` in a **post-hoc pass after the main loop completes successfully** (see `REQUEST_SIMULATOR.md` §7 for the exact call site and its confirmed node-selection bug) — it is not part of the per-hop traversal loop the way `checkNetworkFirewalls` is.

## 5. What is genuinely "current AWS behavior" vs. simplified here

| Real AWS behavior | This codebase | Verdict |
|---|---|---|
| NACL rules evaluated in ascending rule-number order, first match wins, implicit final DENY-all | Rule-number-ascending first-match: **CONFIRMED accurate**. Implicit final deny-all: **NOT modeled** — no-match falls through to allow. | APPROXIMATION |
| NACLs are stateless (return traffic needs its own explicit rule) | Modeled explicitly via `checkCustomNaclReturn`, but only exercised in one specific post-loop code path, not universally on every response leg of every request | PARTIAL / CONFIRMED for the one scenario it targets |
| Security Groups are stateful (return traffic auto-allowed) | Never needs modeling separately because the engine only ever evaluates the forward/inbound leg for SGs — no explicit outbound SG check exists at all, which is consistent with "return traffic is automatically allowed" but also means outbound SG rules (egress) are entirely unmodeled | APPROXIMATION (egress not modeled) |
| SG attachment is by explicit reference (ENI-level), independent of subnet placement | Fully accurate — explicit `securityGroupIds`, no geometry involved | CONFIRMED |
| Subnet CIDR is a fixed, manually-assigned block per subnet | Fully derived from live geometry every render, auto-carved by `allocateSubnetCidrs` | INTENTIONAL SIMPLIFICATION for teaching purposes — real AWS lets you assign arbitrary non-uniform subnet CIDRs; this app always splits evenly by power-of-two count |
| AWS reserves exactly 5 addresses per subnet, in these 5 specific roles | Fully accurate, all 5 roles and offsets correct including the `/31` and `/32` edge cases | CONFIRMED |
| Minimum subnet size is `/28` | Fully accurate, explicitly enforced with a descriptive error rather than a silent wrong answer | CONFIRMED |
