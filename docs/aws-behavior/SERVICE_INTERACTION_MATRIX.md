# SERVICE_INTERACTION_MATRIX.md

For each of the 28 simulator-relevant services: what can call it, what it can call, required networking, required IAM authorization, and key configuration constraints. Sourced from `SERVICE_BEHAVIOR.md` and `NETWORKING_BEHAVIOR.md`; this file is the consolidated cross-reference view, not a new source of claims. All rows CONFIRMED unless noted.

| Service | What can call it | What it can call | Networking required | IAM required | Config constraints |
|---|---|---|---|---|---|
| CloudFront | Any public HTTP/HTTPS client | Its configured origin(s): S3, ALB, custom HTTP, MediaStore | None of its own (global edge); origin may require public reachability or OAC/VPC-origin config | Distribution mgmt: `cloudfront:*`; origin access typically via origin's own resource policy (e.g. S3 bucket policy trusting the distribution) | Cache behaviors matched by path pattern, first-match-wins, order matters |
| Route 53 | Any DNS resolver (recursive or client-side) | N/A — resolves to a target, does not itself call anything | None (global DNS service) | `route53:*` for zone/record management | Alias records only at zone apex for AWS targets; failover policy requires configured health checks |
| AWS WAF | N/A — attaches to and inspects traffic for another resource | N/A — inline inspection, doesn't call out | None (operates within the associated resource's request path) | `wafv2:*`; association permission on the target resource | Rule priority order determines evaluation; Block short-circuits |
| AWS Shield | N/A — transparent edge protection | N/A | None | `shield:*` (Advanced subscription) | Standard is automatic/no config; Advanced requires subscription + resource association |
| EC2 | ALB/NLB (as a target), direct clients (if public + SG allows), other VPC resources | Any AWS API its instance profile role permits; any network destination its SG/NACL/route table allow | Subnet (exactly 1 at launch), Security Group(s), route table | Instance profile role (optional but typical for AWS API calls) | 1 primary ENI/subnet at launch; vCPU quota per instance family |
| ECS (on EC2 or Fargate) | ALB/NLB, EventBridge, Step Functions, direct invocation via awsvpc ENI if reachable | Any AWS API its task role permits | `awsvpc` mode: one ENI per task, in a chosen subnet, own Security Group(s) | Task role (application permissions) + task execution role (pull image, write logs) — two distinct roles, commonly confused | Cluster capacity provider config; service desired-count vs. task placement |
| AWS Fargate | Same as ECS (a launch type of ECS/EKS) | Same as ECS | Same `awsvpc` model as ECS | Same as ECS | No customer-visible host; vCPU/memory specified per task from a fixed set of valid combinations |
| AWS App Runner | Public internet (default) | VPC resources via a VPC connector; any AWS API its instance role permits | None by default (public); VPC connector for private egress | App Runner instance role | No customer-managed ALB/ASG — fully abstracted |
| AWS Lambda | API Gateway, ALB, S3 events, SQS, SNS, EventBridge, Step Functions, direct SDK `Invoke` call, DynamoDB Streams | Any AWS API its execution role permits; VPC resources if configured with subnets | None by default (Lambda-managed network with internet access); VPC config replaces this with subnet/SG-governed private access (loses default internet access) | Execution role (what it can call) + resource-based policy (who can invoke it) | Max 15 min timeout; VPC config requires ENI capacity in target subnets |
| Application Load Balancer | Public internet (internet-facing) or VPC-internal clients (internal) | EC2, ECS/Fargate tasks (via target groups), Lambda functions, IP targets | ≥2 subnets across ≥2 AZs; own Security Group | `elasticloadbalancing:*` | Health-check config independent of any ASG/ECS scheduler health check |
| Network Load Balancer | Public internet, VPC-internal clients, or a VPC Endpoint Service consumer | EC2, ECS/Fargate tasks, IP targets | ≥2 subnets across ≥2 AZs; one static IP/EIP per AZ | `elasticloadbalancing:*` | Required front-end for a PrivateLink VPC Endpoint Service |
| Amazon API Gateway | Public internet (default) or VPC Interface Endpoint clients (private API) | Lambda, any HTTP backend, other AWS service APIs directly | None by default (public/managed); private API requires a VPC Interface Endpoint | Resource policy + IAM/Lambda-authorizer/Cognito per method | 29-second hard integration timeout to backend |
| Amazon RDS | Application compute (EC2/ECS/Lambda-in-VPC) via its ENI | N/A (a data store; doesn't initiate outbound app-level calls itself) | DB subnet group spanning ≥2 AZs; Security Group; NACL on its subnet | `rds:*` for management; DB-level auth (username/password or IAM DB auth) is separate from AWS IAM resource permissions | Single-AZ = no automatic failover; Multi-AZ = synchronous standby + DNS-based failover |
| Amazon Aurora | Same as RDS | N/A | Same as RDS | Same as RDS | Storage replicated across multiple AZs unconditionally; "Multi-AZ" mainly concerns reader-instance failover speed |
| Amazon DynamoDB | Application compute; DynamoDB Streams consumers (Lambda) | Lambda (via Streams) | None of its own (no VPC placement); private access via Gateway/Interface VPC Endpoint | `dynamodb:*` per table/action, standard IAM (no separate DB-level auth layer the way RDS has) | Multi-AZ replication unconditional; throttling is the primary capacity-related failure mode |
| Amazon S3 | Application compute, CloudFront (as origin), any authorized principal | Lambda/SQS/SNS/EventBridge via event notifications | None of its own; private access via Gateway/Interface VPC Endpoint | Bucket policy + IAM (+ VPC Endpoint policy if applicable) | One Zone-IA storage class explicitly not AZ-resilient |
| Amazon ElastiCache | Application compute via its ENI | N/A | Subnet, Security Group, NACL | `elasticache:*` for management; in-cluster auth (Redis AUTH/ACLs) separate from AWS IAM | Multi-AZ (Redis replication group) is opt-in, not automatic |
| Amazon SQS | Any authorized producer (application, SNS subscription, S3 event notification) | N/A (passive; consumers poll it) | None (public API endpoint) or Gateway/Interface VPC Endpoint for private access | Queue resource policy + IAM `sqs:SendMessage`/`sqs:ReceiveMessage` etc. | Visibility timeout must exceed consumer's expected processing time or duplicate delivery results |
| Amazon SNS | Any authorized publisher | Delivers to SQS, Lambda, HTTP/S, email, SMS, push endpoints | None (public API endpoint) | Topic resource policy + IAM `sns:Publish` | Push-based; per-subscriber independent delivery/retry |
| Amazon EventBridge | AWS services (native), custom apps (PutEvents), SaaS partners | Lambda, SQS, SNS, Step Functions, 20+ target types | None (managed, no VPC placement) | Rule/target permissions + resource policy on the event bus for cross-account | Event pattern matching is content-based, not just event-type based |
| AWS Step Functions | Direct `StartExecution` call, EventBridge, API Gateway | Lambda, other AWS service APIs directly (via optimized/AWS-SDK integrations), nested state machines | None (managed, no VPC placement) | State machine execution role (what it can call on your behalf) | Standard: up to 1 year execution, exactly-once; Express: up to 5 min, at-least-once |
| Internet Gateway | N/A (a gateway target, not something "called") | N/A | Attached to exactly 1 VPC; requires a route (`0.0.0.0/0 → igw`) in relevant route tables | `ec2:AttachInternetGateway`/`DetachInternetGateway` | Resource needs a public IP for the IGW's 1:1 NAT to apply — attachment alone insufficient |
| NAT Gateway | Private-subnet resources (outbound-initiated only) | Internet (via its own IGW route) | Lives in a public subnet; private subnets route `0.0.0.0/0` (or narrower) to it | `ec2:CreateNatGateway` | AZ-scoped — no automatic cross-AZ failover for a single NAT Gateway |
| S3 Gateway VPC Endpoint | Resources in subnets whose route table references it | S3/DynamoDB (only these two) | Route table entry (prefix list), no ENI/Security Group | Endpoint policy (optional) + underlying S3/IAM auth still applies | S3 and DynamoDB only — no other service |
| PrivateLink (Interface VPC Endpoint) | Resources in subnets with network access to the endpoint's ENIs | The specific backing service the endpoint targets | ENI per AZ in chosen subnets; Security Group on the endpoint's ENIs; private DNS (optional) for transparent hostname resolution | Endpoint policy (optional) + underlying service IAM auth still applies | Billed hourly + per-GB, unlike the free Gateway Endpoint |

## Simulator-specific discrepancy flags (cross-referenced from `SERVICE_BEHAVIOR.md`)

- ALB "all targets unhealthy" real status code is **503**; this simulator's own code returns **502** for this case (`docs/codebase/REQUEST_SIMULATOR.md` Behavior 5) — a confirmed discrepancy worth a conformance test.
- `waf`/`shield` are modeled identically in the simulator; real Shield does not perform the L7 signature inspection WAF does — a confirmed conflation.
- ECS/Fargate task replacement is sometimes narrated by the simulator as "the Auto Scaling Group" doing it (`docs/codebase/REQUEST_SIMULATOR.md` Behavior 5's ALB explanation text) — the actual mechanism for ECS/Fargate tasks is the ECS **service scheduler**, a distinct system from EC2 Auto Scaling Groups.
- RDS Multi-AZ failover is documented by AWS as typically 60-120 seconds; the simulator narrates ~35 seconds — faster than AWS's own documented typical range.
